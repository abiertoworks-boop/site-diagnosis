# Webサイト診断(URLを入れると診断レポートと改善イメージを作る)

URLを入れると、次の3つを作ります。

1. 事実にもとづく自動診断(根拠つきの改善点、最大10個)
2. 診断レポート(PDF)
3. 改善後のイメージ画像(現状と並べて比較。変更箇所にオレンジの目印)

## 起動(手元のPC)

| OS | 手順 |
|---|---|
| Windows | PowerShell で `.\run.ps1`(初回は依存のインストールに数分かかります) |
| macOS / Linux | `./run.sh` |

ブラウザで http://127.0.0.1:8000 を開きます。必要なもの: Python 3.11 以上。
手動で入れる場合: `pip install -r requirements.txt` → `playwright install chromium` → `python app/server.py`

## 持ち込みモード(HTML + スクリーンショット)

ボット対策などでURLから診断できないサイト向けです。お客様が自分のブラウザで保存した資料から診断します。サイトにはアクセスしません。AI(外部API)も使いません。

1. 画面上部の『資料を持ち込む』を選びます。
2. HTMLファイル(必須)と、スクリーンショット(必須・複数可)を選びます。画像ごとに『PC/スマホ』を指定できます(固定幅のサイトは、スマホ画面でも画像の幅が大きくなるため、自動判定を誤ることがあります)。
3. 撮り方は、画面内の『撮り方・保存の仕方』に書いてあります。**スクリーンショットは、先にページを最後までスクロールしてから撮ってください**(遅れて表示される部分が白い空白で写るのを防ぐため)。

| 項目 | 持ち込みモードでの扱い |
|---|---|
| title・meta・見出し・OGP・alt・電話リンク・フォーム・FAQ・個人情報・返信目安など | 自動チェック(HTMLの事実) |
| viewport が固定幅(スマホ対応) | 自動チェック |
| ファーストビューのCTA・固定表示・色のコントラスト・タップの大きさ | **判定しない**(未検証と表示) |
| 『誰向けか』『強み』など | 要確認(担当者が画像を見て判断) |
| 改善イメージ | スクリーンショットの上に、連絡バーなどを描き足した**例**(現状に既にあるかは確認できません) |

セキュリティ: アップロードされたHTMLは**実行せず**、文字として解析します。画像は PNG・JPEG・WebP のみ、8枚まで、合計60MBまで。

## 設定(環境変数)

| 名前 | 意味 |
|---|---|
| `SD_PORT` | ポート(既定 8000) |
| `SD_HOST` | 待ち受けアドレス(既定 127.0.0.1)。外部に公開するときだけ 0.0.0.0 |
| `SD_PASSWORD` | 設定すると、画面とAPIに認証(Basic)がかかる。**外部公開時は必須**(未設定だと起動しない) |
| `SD_JOBS_DIR` | 結果の保存先(既定 `app/jobs`)。24時間で自動削除 |

## 診断の流れ

1. トップと主要ページ(最大5ページ)を取得し、HTMLから事実を抽出(`scripts/collect.py`)
2. Chromium で PC(1366px)・スマホ(iPhone相当・390px)を1回ずつ開き、画面を計測(`app/capture.py`)
3. 事実のチェック(`app/checks.py`): 電話のタップ可否、ファーストビューのCTA、コントラスト比、見出し、meta、FAQ・個人情報・返信目安の有無など
4. 改善イメージ(`app/mockup.py`): 同じ画面の上に、見つかった問題の改善案を重ねて撮影
5. PDF(`scripts/make_pdf.py`)

## できないこと・限界(必ず読んでください)

- **自動診断は事実のチェックだけです。** 『誰向けか』『強み』『ベネフィット』『導線』『ファーストビュー』は、スコアカードで『要確認』と表示します。担当者が画面を見て判断します。
- **改善イメージは『簡易な差し込み』です。** 自動でできる変更は、固定の連絡バー、ファーストビューへのCTAボタン、コントラスト不足の調整、電話のタップ化、見出し下の説明文(サイト自身の meta description を使用)の5種類のみです。デザイン案そのものの自動生成はしません。
- **ボット対策(確認ページ・429など)のあるサイトは診断できません。** 検出して止まります。回避はしません。同じサイトを30分以内に続けて診断できないのは、このためです(実際に、短時間に何度も取得して確認ページに止められました)。
- 判断が必要な表現(性能の断定、パートナー募集、広告表現など)の法的な適否は判断しません。『専門家に確認』と書きます。
- 診断対象は、自分のサイト、または診断の許可を得たサイトに限ってください(画面で同意を求めています)。
- 内部ネットワークへのアクセス(`127.0.0.1`、`10.x`、`169.254.x` など)は遮断します。ただし、DNS の切り替え(DNS rebinding)への対策は不完全です。**外部公開するときは、サーバーの外向き通信を制限してください。**
- 動作確認は Linux 上で行いました。**Windows・macOS では未確認**です。
- 診断の精度は、手作業での診断(`skill/SKILL.md`)と同じ観点で作っていますが、手作業ほど文脈は読めません。

## フォルダ

```
app/server.py      Webサーバーと画面のAPI
app/static/        画面(index.html)
app/pipeline.py    URL診断の全工程
app/upload.py      持ち込みモードの全工程
app/capture.py     ブラウザでの計測
app/checks.py      事実のチェック(改善点の根拠)
app/mockup.py      改善イメージ
app/fonts/         日本語フォント(IPAゴシック。ライセンスは同梱の LICENSE-IPAFont.txt)
scripts/           HTML解析・PDF作成(単体でも使える)
skill/SKILL.md     手作業で診断するときの手順と、これまでに見つけた落とし穴
```
